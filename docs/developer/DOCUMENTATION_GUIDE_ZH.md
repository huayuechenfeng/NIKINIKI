# NIKINIKI 文档维护约定

> 状态：Active
> 本页职责：规定文档分类、唯一事实来源和变更流程

## 信息分层

| 层级 | 目录 | 是否描述当前状态 | 允许的变化方式 |
|---|---|---:|---|
| 门户 | `docs/README_ZH.md` | 否 | 只调整导航 |
| 活文档 | `STATUS_ZH.md`、`ROADMAP_ZH.md`、`developer/`、`user/` | 是 | 原位更新结论 |
| 决策 | `decisions/` | 是 | 新增 ADR 或标记 Superseded |
| 参考 | `reference/` | 部分 | 更新表格或固定基线 |
| 研究 | `research/` | 否 | 保留当时证据，增加结论边界 |
| 发布 | `releases/` | 仅对应版本 | 发布后原则上不改事实 |
| 归档 | `archive/` | 否 | 只作追溯，不继续追加 |

## 唯一事实来源

- 当前能力、已知限制：`STATUS_ZH.md`；
- 工作优先级：`ROADMAP_ZH.md`；
- 当前模块和播放器结构：`developer/`；
- 真机结果：`reference/DEVICE_TEST_MATRIX.md`；
- 工具链：`reference/TOOLCHAIN_REPORT.md`；
- 发布包、大小、校验值和签名：对应 `releases/RELEASE_*.md`；
- 实验测量和失败路径：`research/`。

其他文档只链接这些来源，不能维护第二份数值或状态表。

## 活文档写法

每份活文档开头至少声明：

```markdown
> 状态：Active
> 适用版本：1.0.0 与当前主线
> 本页职责：……
```

写作规则：

1. 标题和文件名描述长期主题，不带临时版本号或会话日期；
2. 结论变化时修改原章节，不在末尾追加“某日更新”；
3. 删除当前正文中的旧路线，把证据移到 research/archive；
4. 使用“已静态检查”“已 GCCE 构建”“已打包”“已真机验证”等精确状态；
5. 预期、目标、探针结果和正式产品结果必须明确区分；
6. 活文档接近 200～250 行时检查是否混入了第二种职责；
7. `docs/README_ZH.md` 的核心接手顺序保持在三份以内。

## ADR 规则

ADR 用于长期影响多个模块、或未来很可能被重新质疑的决定。每份包含：

- 状态：Accepted、Superseded 或 Rejected；
- 背景；
- 决定；
- 后果；
- 支撑证据和替代决定。

新证据改变既有决定时，不重写历史 ADR；新增 ADR，并把旧 ADR 标记为 Superseded。

## 研究文档规则

研究文档可以保留版本号、实验代号、日志编号和当时的失败假设，但必须明确：

- 它不代表当前实现；
- 当前结论链接到哪份活文档；
- 哪些数据是测量值，哪些只是推断；
- 探针、Debug 包和历史 SIS 不能作为发布基线。

历史中的 `wiliwili for Symbian³` 名称按原样保留，不做机械替换。

## 变更检查清单

修改产品行为后：

1. 更新一份对应活文档；
2. 如果改变长期设计，新增或修订 ADR 状态；
3. 如果产生真机结论，更新设备测试矩阵；
4. 如果发布新版本，只在对应发布说明写包大小和哈希；
5. 更新所有 Markdown 链接并检查不存在旧根路径；
6. 确认历史文档没有被重新列入必读顺序。

会话级改动优先留在 Git 提交或 PR 中；只有具有长期诊断价值的内容才整理为 research 文档。

提交前运行：

```powershell
.\tools\Test-Documentation.ps1
```

该脚本检查本地 Markdown 链接、核心活文档是否存在，以及活入口是否重新引用已退役的旧根路径。
