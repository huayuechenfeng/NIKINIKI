## 本版修复

1. **主界面无字体**
   - 优先按正在运行的 EXE 盘符读取完整字体，并依次检查 Belle 常见数据盘。
   - 如果安装盘字体仍不可读，直接使用 EXE 内嵌的 8,710 字符子集，不再出现整个
     NanoVG 主界面无字。
   - Debug 日志会输出 `WW:FONT_CANDIDATE` 和 `WW:PRIMARY_FONT_READY`，可区分
     完整字体与内嵌兜底。

2. **视频盖住进度条和设置**
   - Belle MMF 的 `QVideoWidget` 是原生窗口，普通 Qt 同级控件无法可靠压在它上面。
   - 控制层隐藏时，视频仍使用全部屏幕；控制层显示时，原生视频窗口会让出顶部和
     底部安全区；打开清晰度菜单时再让出右侧区域。这样进度、返回、清晰度、弹幕和
     倍速按钮不会再被视频层遮住。

3. **点击后控制层一闪即逝**
   - 按下时记录点击前的显示状态，松开时依据该状态切换；不再发生按下先显示、松开
     又立即隐藏的双重切换。

4. **退出视频后黑屏**
   - 播放期间不再隐藏主页 `QGLWidget`，避免 Belle 销毁其 EGL surface。
   - 退出先隐藏 MMF 视频窗口并清空媒体，再恢复方向、主页前台和 OpenGL 重绘。
   - 同时取消尚未结束的清晰度、直播或弹幕请求，避免退出后延迟回调重新打开播放器。

5. **部分视频有声无画**
   - 新安装/升级后的普通视频默认档改为 480P（Q32），不再继承旧版保存的 720P。
   - 播放状态有声音但连续 6 秒没有视频输出时，按接口提供的档位自动降到 360P，必要
     时再降到 240P；日志为 `WW:PLAYER_VIDEO_MISSING_FALLBACK`。
   - 这能规避部分 Nokia 603 MMF 不支持的 H.264 分辨率/profile，但不能让固件解码器
     支持其本来不支持的编码格式。

## 建议真机验证顺序

1. 完整安装 Debug SIS，应用管理器中确认版本为 0.6.1；不要只覆盖 EXE。
2. 从手机图标冷启动三次，确认每次主界面都有字体。
3. 打开一个此前可正常显示画面的视频，点击屏幕，确认控制栏保持显示且可以操作。
4. 打开清晰度菜单，确认右侧菜单不被视频盖住；再点空白处让控制层隐藏，确认视频恢复
   全屏区域。
5. 返回详情页，确认不是黑屏，并再次进入同一视频。
6. 测试此前“只有声音”的视频，观察右上角是否先显示 `AUDIO`，以及是否自动从 480P
   降到 360P/240P 后出现画面。
7. 若仍有问题，只需保留 `WW:FONT_*`、`WW:PLAYER_*` 与 MMF 错误日志，不要发送
   Cookie。
